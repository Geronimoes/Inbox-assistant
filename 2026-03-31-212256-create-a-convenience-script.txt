● Here are three approaches:

  ---
  Option A: Pure bash script (simplest)
  A single inbox file in the project root using bash's built-in select for the
  menu. Activates the venv and runs the chosen command. No Python involved in
  the menu itself.
  - Pro: zero dependencies, very short file, easy to read
  - Con: harder to add color/formatting, limited control over UX, bash quirks

  ---
  Option B: Bash wrapper + Python menu (recommended)
  An inbox shell script (thin wrapper) that activates the venv and delegates to
  src/menu.py. The Python script renders a numbered menu with ANSI color,
  grouped by category, and runs the selected command. No external packages —
  just stdlib.
  - Pro: clean categories with color, easy to extend, Python is already the
  project language, the menu logic lives where it belongs
  - Con: two files instead of one (but small ones)

  ---
  Option C: Full TUI with curses
  A Python curses app with arrow-key navigation and highlighted selection.
  - Pro: feels polished
  - Con: significantly more code, curses can be finicky over SSH, overkill for
  ~15 menu items

  ---
  My recommendation: Option B. The bash wrapper is 5 lines; all the real logic
  is in src/menu.py which is already "home" for project code. Grouped, colored
  output makes 15 commands scannable at a glance, and it's easy to add new items
   later. The PATH install becomes a one-liner in the optional install step.

● Design — Section 3: Venv handling & PATH install

  Venv activation (bash wrapper):
  The inbox script uses realpath to resolve symlinks, so it always finds the
  project root regardless of where it's called from. It then sources
  env/bin/activate and hands off to Python. If the venv doesn't exist it prints
  a clear error:
  Error: virtualenv not found at <project>/env/
  Run: python3 -m venv env && pip install -r requirements.txt

  PATH install (option i in menu):
  Creates a symlink: ~/.local/bin/inbox → 
  /home/jeroen/projects/inbox-assistant/inbox. If ~/.local/bin doesn't exist
  it's created. If a symlink already exists it's updated. Prints a note if
  ~/.local/bin isn't in $PATH yet (one-time setup).

  Running commands:
  subprocess.run() with inherited stdin/stdout/stderr — live output streams
  directly to the terminal, exactly as if you ran the command manually. After it
   exits, shows the return code if non-zero (so failures are visible), then
  "Press Enter to return to menu."
